## 三、调研结论（未改代码部分）

### 开机自启（静态结论：主路径可用，但有确定缺陷）
- 插件 Builder 链注册、`MacosLauncher::LaunchAgent`、`ManagerExt::autolaunch()`、capabilities 均正确；v0.7.0 的「插件未注册」根因已修
- 已修：前端把失败吞成 `false` 导致「系统已启用 / UI 显示关闭」、Rust 查询吞错
- 仍存在（需真机验证 / 产品取舍）：`prefs.autostart` 只是镜像，启动时不对齐系统，重装/换安装包/手动删启动项会静默丢失勾选；上游 `is_enabled()` 只查注册文件存在、不校验目标 exe 路径；`runAsAdmin=true` 叠加时每次登录触发 UAC，不确认则自启实质失效；项目无 `Cargo.lock`，插件版本不可复现
- 本机无桌面会话，无法真机注销→登录验证

### 内置优质音色 —— 微软「晓晓」不能内置
- `zh-CN-XiaoxiaoNeural` 是 Azure / Edge **在线**神经 TTS 音色，模型在微软云端，不提供离线包；必须联网调用，微软服务条款也不允许把合成语音随应用再分发
- 可落地选项：①系统内置中文语音（0 字节，但 Linux 常缺、音质参差）；②预生成固定话术离线音频片段（报时话术有限，约 1–3MB，音质可做到接近晓晓，需**用可商用授权的开源 TTS 生成**以规避许可）；③离线 TTS 引擎 sherpa-onnx / Piper 中文模型（约 30–70MB，可念任意文本，集成复杂、需核对各模型许可证）
- 推荐：固定报时用 ②，任意文本（提醒内容）回退 ①；若坚持「接近晓晓 + 任意文本」，用用户自己的 Azure 订阅在线调用（需联网 + 用户自己的 key），不做内置

### 闹铃语音兼容（可选项，考察结论）
- 可行且改动小：现有 `alarmSound` 是 Web Audio 合成音，与 `speechSynthesis` 独立；在 `showAlarmToast` 里对提醒内容调 `Announce.speak(note)` 即可
- 需处理：铃声与语音叠加（先静音/降音量，播完恢复）、免打扰时段、响铃自动停止计时与语音时长对齐、停止闹铃时一并 `speechSynthesis.cancel()`

### 托盘双击的平台硬限制
- Tauri 官方 `TrayIconEvent::DoubleClick` **仅 Windows**；macOS 无原生双击事件（已用 400ms 双击判定兜底）；**Linux 完全不发出托盘点击事件**（已用菜单项兜底）
- `show_menu_on_left_click(false)` 只影响左键，右键菜单行为需真机确认

### 其他发现（全局审查，未修，按严重程度）
- P1：`calendarAutoSync` Rust 字段缺失（**已修**）；定时任务 Rust 侧不去重 / 取消失败仍广播成功；提权取消后单实例锁未恢复（可能出现双进程）；隐藏窗口仍每秒跑校时页 interval；一键更新失败仍退出（**已修**）
- P2：日历数据校验不查年份连续与 MMDD 合法性；`normalize()` 对 `style/backdrop`/时间范围/数值类型消毒不足；窗口 id 与几何参数缺统一 sanitize；文档承诺「一次性」规则但 `MODES` 不含 `once`；自定义负时区标签漏 `-`；`open_update_installer` URL 校验偏弱；`timer-cancelled` 无前端监听；启动时自动校时前后端各跑一次；铃声试听 timeout 未清理；多处注释仍写「v0.7 未发布」而当前已 v0.7.4；`Alarm.check()` 等旧死代码
- 未发现问题：跨午夜静音、闰年/节假日派生、i18n 词条缺失、HTML 注入（全项目无 `innerHTML`/`eval`）、shell 注入、主版本号一致性
