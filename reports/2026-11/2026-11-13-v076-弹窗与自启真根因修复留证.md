## 一、真根因（均有官方/上游源码坐实，非猜测）

### ① 弹窗不显示：同步命令里建窗，Windows WebView2 死锁
- 官方 `docs.rs/tauri::webview::WebviewWindowBuilder::build` 原文：
  > On Windows, this function deadlocks when used in a synchronous command or event handlers, see the Webview2 issue. You should use async commands and separate threads when creating windows.
- 旧 `show_alert` 是 `#[tauri::command] **fn**`（同步）且**直接 `.build()`**：主线程自己等自己 → 死锁 → 窗口根本没被创建、IPC 永不返回，界面永远不出现。
- 项目里 `add_clock_window`、`ensure_settings_window`、托盘菜单早已用 `std::thread::spawn` 规避（代码注释里明确写了这个坑），**唯独提醒窗漏了**。
- 前两轮改透明/尺寸/超时都作用在「窗口已创建之后」，对「窗口压根没创建」完全无效 → 症状不变。

### ② 开机自启失败：上游 auto-launch 0.6.0 写注册表路径不加引号
- 实拉 crate 源码核对：`auto-launch-0.6.0/src/windows.rs` 的 `enable_with_root_key()`：
  ```rust
  root_key.create(AL_REGKEY)?.set_string(
      &self.app_name,
      format!("{} {}", &self.app_path, &self.args.join(" ")),   // 没有引号
  )?;
  ```
- `tauri-plugin-autostart 2.7.0` 传的是 `current_exe().display().to_string()`，默认 `WindowsEnableMode::Dynamic`（提权时写 HKLM）。
- 安装目录含空格（`C:\Program Files\...`、用户名带空格等）→ Windows 登录时把 `C:\Program` 当可执行文件，静默跳过。
- 更误导的是 `is_enabled()` **只检查该注册表值是否存在**（外加 StartupApproved 字节），不校验命令是否有效 → 界面显示「已开启」，重启却不启动，正是主人看到的现象。
- 叠加「始终以管理员身份启动」（`RUNASADMIN` 兼容层）时，登录阶段还会被 UAC 拦截。
- 注册表值名核对：插件用 `app.package_info().name` = Cargo 包名 `desk-clock`。
