## 二、真凶：RUNASADMIN 兼容层

逐条对照可知**注册表这一层已经完全正确**：

| 环节 | 状态 | 判定 |
|---|---|---|
| Run 值名 | `Desk Clock`（= productName） | ✅ v0.7.7 已修对 |
| 命令带引号 | 是 | ✅ v0.7.6 已修对 |
| 目标路径存在 | 是 | ✅ |
| StartupApproved | 02（启用） | ✅ v0.7.7 已修对 |
| 历史错值名 | 无 | ✅ v0.7.7 已清理 |
| **AppCompatFlags\Layers = RUNASADMIN** | **存在** | ❌ **真凶** |

`RUNASADMIN` 的语义是「这个 exe 每次启动都要弹 UAC 提权」。
而在**登录阶段**（开机自启），系统还没有交互桌面可以弹 UAC，
Windows 就会把这个启动项**静默跳过** —— 于是：

- 注册表一切正常 → 火绒/任务管理器都显示「已启用」
- 但 Windows 压根没去执行它 → 任务管理器搜 "Clock" 零结果、桌面没有时钟
- `startup.log` 只有 `MANUAL` 从没有 `AUTOSTART` → 证明 Windows 从没在登录时拉起它

这与主人观察到的现象**逐条吻合**。

### 为什么这是我的责任

`RUNASADMIN` 是**本程序自己写的**：`set_run_as_admin()` → `set_admin_compat(true)`
在 `HKCU\...\AppCompatFlags\Layers` 给当前 exe 打标记（用于「始终以管理员身份启动」功能）。
v0.7.7 只清了 `StartupApproved`，没碰这一层 —— 而恰恰是这一层在登录阶段拦死了自启。

### 为什么「自愈」救不了（结构性死锁）

v0.7.7 的自愈写在 `.setup()` 里，**只有程序已经启动才会执行**：

```
开机自启坏 → 程序永远起不来 → 自愈永远不执行 → 永远修不好
```

自愈在结构上无法打破这个循环。真正能打破它的只有**安装器**（覆盖安装时由安装器写好启动项）。

## 三、v0.7.8 的修复

| 层 | 改动 | 文件 |
|---|---|---|
| 注册表写入 | `repair_windows_run_value()` 额外清掉本 exe 的 RUNASADMIN | `src-tauri/src/lib.rs` |
| 开启自启 | 新增 `set_autostart_ex`：先清 RUNASADMIN → 再写 Run 值 → 回传 `clearedAdminMode` | 同上 |
| 互斥保护 | `set_run_as_admin()` 在自启已开时直接报错 `ADMIN_AUTOSTART_CONFLICT`，说明「登录时弹不出 UAC」 | 同上 |
| 启动自愈 | Run 值健康但存在 RUNASADMIN 时同样清理 | 同上 |
| 诊断 | 新增 `adminCompatBlocking` 字段；界面直接点名真凶 | `lib.rs` / `ui/app.js` |
| 界面 | 开启自启时若清掉管理员模式，明确告知用户（不做黑箱操作）；管理员开关与自启冲突给中文可执行提示 | `ui/app.js` / `ui/prefs.js` |
| **安装器** | NSIS `NSIS_HOOK_POSTINSTALL` → `_DC_WRITE_AUTOSTART`：当用户此前已登记过开机自启时，写入带引号的 `"<安装目录>\desk-clock.exe" --startup`、清 StartupApproved、删历史错值名、清 RUNASADMIN —— **由安装器打破鸡生蛋死锁** | `src-tauri/windows/hooks.nsh` |

设计取舍：**安装器不擅自给新装用户开自启** —— 触发条件是注册表里已存在「Desk Clock」/历史错值名，
即用户确实表达过这个意图，只是让安装器把它**纠正**而不是新增。

## 五、附带修正：诊断工具自身崩溃（主人 16:28 反馈）

主人运行 v2 工具时看到 `'1' 不是内部或外部命令` / `'[閩樂團]' 不是...` 乱码报错。
根因是**我的包装脚本有编码缺陷**：`fix-autostart.cmd` 里既写了中文、开头又执行 `chcp 65001`，
cmd.exe 切换代码页后会**从文件中间的字节偏移重新读取批处理文件**，
于是后面的中文被错切、碎片被当成命令执行。

v3 修正：
1. `.cmd` 改为**纯 ASCII**（0 个非 ASCII 字节），中文输出全部移到 `.ps1`，启动器里不再有 `chcp`；
2. `.ps1` 存成 **UTF-8 with BOM + CRLF**，Windows PowerShell 5.1 不会把中文读成乱码；
3. 脚本自动请求管理员权限（弹 UAC 点「是」即可，不必手动右键）；
4. 已用**真实 PowerShell 7.4.6 官方 parser** 校验 `PARSE_OK`，并整脚本干跑：7 步全通、
   中文正常显示、报告文件正常落盘、「找到 exe / 找不到 exe」两条分支都验过。
