官方口径（本次实查）：
- Tauri 官方 Windows Installer 文档：`.msi` 只能在 Windows 生成（WiX 只能跑 Windows）；NSIS 可从 Linux/macOS 交叉编译，但明确标注 "not as straight forward ... not tested as much ... should only be used as a last resort if local VMs or CI solutions like GitHub Actions don't work for you"。交叉编译需 `nsis` + `lld`/`llvm` + `rustup target add x86_64-pc-windows-msvc` + `cargo install --locked cargo-xwin`，产物在 `target/x86_64-pc-windows-msvc/release/bundle/nsis/`。
- macOS DMG/App 需 macOS 主机 + 代码签名/公证，Linux 无法产出。
- Azure DevOps 官方：Microsoft-hosted 免费层私有项目 1 个并行 job、单次 60 分钟、每月 1800 分钟；**公开项目已退役**（2027 转私有），且免费额度需绑定有效 Azure 订阅才能启用。self-hosted 免费层无时间限制。
- GitLab 官方：Free 层 400 compute minutes/月、10 GiB 存储；自有 runner 不计额度且不限量。
- CircleCI 官方：开源计划 Linux/Arm/Docker 40 万 credits/月，macOS/Windows 3 万 credits/月。
- AppVeyor 官方：所有计划单 job 上限 60 分钟，FOSS 计划额外并发 $25/月。

## 二、⚠️ 换平台不只是改 CI：代码里有 6 处 GitHub 硬依赖

只换打包平台不改代码，会导致「一键更新」和「日历自动同步」直接失效：

1. `src-tauri/src/lib.rs` `validate_update_url()`：白名单只认 `https://github.com/xiaoqiangclub/desk-clock/releases/download/` —— 换平台后自动更新校验会拒绝所有 URL。
2. `src-tauri/src/lib.rs` `open_link()`：`project` / `releases` 硬编码 github.com。
3. `ui/prefs.js` `checkUpdate()`：`fetch('https://api.github.com/repos/xiaoqiangclub/desk-clock/releases/latest')`。
4. `ui/calendar-sync.js` `RAW_URL`：raw.githubusercontent.com，备源由主 URL 派生为 jsdelivr `gh/` 路径 —— 换平台后备源也会失效。
5. `.github/workflows/calendar-sync.yml`：定时同步 GitHub 仓库里的日历数据。
6. `README.md` / `CHANGELOG.md` / `release.yml`：下载链接与文档指向 GitHub Releases。

另外：**包打出来发到哪里**也是硬问题。GitHub Releases 不可用，需要替代分发（对象存储直链 / 网盘 / 飞书文件直传 / 自建静态站）。只换 CI 不解决分发。

## 三、推荐路线（按性价比）

1. **短期（现在）**：等申诉结果；已有持久锚点 `2be731d3-04e9-4268-9dff-27c934bb260c` 每小时静默探测，恢复即自动 push + tag 触发现有四平台 workflow，零改造。
2. **本次救急**：用 InstaBox 云主机打 Linux 包（deb/rpm/AppImage）并做 Rust 编译验证；Windows 包若急需，试 NSIS 交叉编译（实验性，不保证成功）。
3. **长期双活（建议）**：申诉恢复后把 GitHub Actions 作为主链路，另建 Azure Pipelines 免费层做**备用打包**（同一份代码、产物双份），并把上述 6 处硬依赖抽象成「分发源配置」，避免再次单点失效。这样以后任何一侧被封都不至于完全停摆。
4. **不建议**：现在立刻把仓库整体迁到新平台并批量注册新账号——账号正在申诉期，跨平台关联注册可能加重判定。
