# 多窗口完整配置设计（v0.6.0）

## 意图与为什么

用户反馈：新增的多时区窗口只能改「时区 / 样式 / 显示秒」，位置、颜色、字体、大小、透明度等都改不了；主窗口连时区都不能设。继续打补丁会让「主窗口特殊、额外窗口残缺」越来越乱。

目标：**所有时钟窗口完全平等**——每个窗口都有一份完整配置，主窗口只是默认存在的那一个（也能设时区/位置/颜色等全套）。以后新增任何设置项，自动对每个窗口生效。

## 目标 / 非目标 / 反目标

- 目标：每窗口独立保存并应用全部视觉/位置/时区项；设置界面可切换「正在编辑哪个窗口」；管理器每行可直达该窗口的设置；主窗口纳入统一管理。
- 非目标：不改单实例、不改托盘、不改固定设置窗口尺寸、不改打包流程。
- 反目标：不能因为窗口能设置了就重新挡住其它应用的点击（额外窗口仍默认鼠标穿透）；不能让旧配置在升级后丢失。

## 设置项归属（关键决策）

**全局（一次设置，程序级）**：界面语言、闹钟列表与铃声、定时关机/重启、启动时自动校时、开机自启、始终以管理员身份启动。

**每窗口（各自独立）**：名称、时区/UTC 偏移、样式、显示秒、12 小时制、显示分隔符、字体/自定义字体、颜色/自定义颜色、表盘配色、指针穿透、背景板、大小、不透明度、总在最前、鼠标穿透、窗口位置 x/y、可见性。

## 约束

- 本机无 cargo/rustc，Rust 只能靠 CI 验证 → 新增后端一律用 `serde_json::Value` 操作，避免结构体/泛型编译风险。
- 保持向后兼容：旧 `prefs.json`（扁平单份）读进来后，自动以它为 `main` 窗口的初始完整配置。
- 前端仍用真实 Chromium 回归；所有状态节点沿用 `data-dyn`。
- 设置窗口固定 760×700；额外窗口鼠标穿透（纯展示 + 拖动/设置入口改为「在设置窗口里编辑」）。

## 方案对比（ Approaches ）

1. **重构 Rust `Prefs` 结构体拆成 Global/Clock 两份**：类型最干净，但要改所有现有命令与字段、编译风险最高，一次 CI 难保证过。放弃。
2. **新增独立 `clocks.json` + `WindowState(Mutex<Value>)`，现有 `PrefsState` 不动**：窗口配置全用 Value 存取，改动集中在新增命令；旧 prefs 继续当全局/默认。风险最低，选中。
3. **纯前端 localStorage 存窗口配置**：跨窗口同步与持久化会失真、重启还原不可靠。放弃。

## 实现方式（选定方案 2）

### 数据
- `clocks.json`：`{ "activeId": "main", "clocks": { "<id>": {<完整窗口配置>} } }`。`main` 恒存在。
- 每个窗口的「完整配置」= 一份含全部每窗口项的 JSON；读取时与全局项合并成一个对象供现有控件直接使用。

### Rust 新增命令（全部 Value，低风险）
`get_window_configs` / `save_window_configs` / `get_window_prefs(id)` / `set_window_prefs(id, patch)` / `get_active_clock` / `set_active_clock(id)` / `set_window_position_for(id,x,y)` / `add/remove/toggle` 窗口（复用并扩展现有 `extra_clocks` 逻辑）。
写入后 `emit("window-prefs-changed", {id, prefs})`，各窗口只应用自己 id；设置窗口应用当前目标。

### 前端
- 每个窗口启动注入 `__DC_CLOCK_ID__`（main 也注入 `'main'`）。
- `Prefs.load()`：时钟窗口按自身 id 取配置；设置窗口按 `activeId` 取配置，合并全局项给控件。
- `Prefs.save(patch)`：按 `GLOBAL_KEYS` 分流——全局项写根 prefs，窗口项写 `clocks[targetId]`。
- 设置窗口头部加「正在编辑：[窗口下拉]」，切换即载入。
- 管理器每行加「设置」按钮 → 设为 activeId 并跳到「外观」Tab。
- `applyRemotePrefs` 只响应与自身 id 匹配（或设置窗口的当前目标）的事件。
- 每个时钟窗口应用自己的 scale/size/position/alwaysOnTop/clickThrough/opacity/颜色/字体/时区。

### 权限与设置项完整性
闹钟、定时、校时、管理员启动等仍为全局，所有窗口共享；不存在「某个窗口缺少某项设置」。窗口的齿轮打开同一个设置窗口，通过目标选择器编辑任意窗口。

## 留给实施者的判断
- 旧 `extra_clocks` 字段迁移到 `clocks.json` 时保留 label/offset/style/showSeconds/visible。
- 新窗口默认配置 = 复制 `main` 当前配置后覆盖时区/名称；避免新窗口「什么都没配」。
- 管理器上限 8 个窗口沿用。
