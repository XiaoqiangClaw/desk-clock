Desk Clock 开机自启 · 诊断与一键修复工具（v2）
================================================

用法（三步）
------------
1. 把这个压缩包解压到「任意位置」都行，但【最好放在 desk-clock.exe 同一个文件夹里】
   —— 这样工具能 100% 找到程序本体；如果放在别处找不到，它会提示你手动粘贴路径。
2. 右键 fix-autostart.cmd →「以管理员身份运行」（推荐）。
   不弹 UAC 也能跑，只是 HKLM 那部分写不了（不影响你的账户自启）。
   若弹出「Windows 已保护你的电脑」：点「更多信息」→「仍要运行」。
3. 看窗口输出，然后：
   - 「启动测试成功：进程已运行」→ 时钟已经在跑，重启电脑验证能否自动出现。
   - 仍不行 → 把【桌面上的 DeskClock-autostart-report.txt】直接发回给我。

它打印什么、每一项对应什么病
--------------------------
[1/7] 程序路径 + 文件版本
      → 版本号不是 0.7.7，说明你装的是旧版，旧版有已知的自启 bug。

[2/7] 注册表 Run 里的原始条目（只打印与 desk-clock 相关的）
      → 「带引号: 否」= 路径里有空格却没加引号，Windows 登录时会把
        C:\Program Files\Desk Clock 当成程序名 → 静默跳过，必失败。
      → 「目标存在: 否」= 启动项指向的程序已被移动/删除/换目录了 → 同样静默失败。

[3/7] 「启动应用已禁用」字节 + 「以管理员身份启动」标记
      → 已禁用：任务管理器里被人关过，登录直接跳过。
      → RUNASADMIN：登录时弹 UAC 无法显示 → 静默失败。

[4/7] startup.log（关键证据）
      → 有 AUTOSTART 行 = Windows 确实在登录时拉起了程序（问题在程序自身/被杀软拦）
      → 只有 MANUAL   = Windows 从来没在登录时拉起它（问题在启动项本身）

[5/7] 修复：写入「带引号的当前 exe 绝对路径」+ 删历史错值名 + 清禁用字节 + 去 RUNASADMIN
[6/7] 备用通道：创建「登录时」触发的计划任务 DeskClock Autostart（双保险）
[7/7] 自检：用与开机完全相同的命令拉起程序，确认进程真的起来

安全说明
--------
只改你自己账户的启动项与一个登录计划任务，不动系统其他配置、不联网、不上传任何数据。
撤销：在时钟设置里关掉「开机自启」；或在任务管理器 → 启动应用 里禁用；
计划任务可在「任务计划程序」里删除名为 DeskClock Autostart 的那一项。
